Agent 智能体工作原理 LangChain

本文档详细介绍项目中 Agent 类型对话的架构设计、核心循环、数据流和扩展方式。

1. 概览

系统支持两种对话类型：Chat（普通对话）和 Agent（智能体）。

Chat 普通对话 Agent 智能体
底层 SDK Vercel AI SDK (ai) LangChain (@langchain/openai)
API 端点 POST /api/chat POST /api/agent
响应格式 纯文本流 (text/plain) NDJSON 流 (application/x-ndjson)
工具调用 不支持 支持，LLM 可自主决定调用工具
多轮交互 单次请求-响应 Agent 循环：LLM → 工具 → LLM → ... → 最终回答

Chat 类型通过 Vercel AI SDK 的 streamText 直接流式返回 LLM 响应。 Agent 类型使用 LangChain 的 Tool Calling Agent 模式：LLM 不仅能回答问题， 还能根据需要调用预定义的工具（如查询天气、计算数学表达式、获取时间、网络搜索等）， 并基于工具返回的结果继续推理，直到给出最终回答。

2. 模块架构

Agent 相关逻辑集中在 app/agent/ 目录下，各文件职责单一：

app/agent/
  index.ts  ← 统一导出（barrel file）
  types.ts  ← 共享类型定义
  llm.ts    ← LLM 客户端创建 + 模型校验
  history.ts ← DB 消息 → LangChain BaseMessage 转换
  executor.ts ← 核心 Agent 循环（调用 LLM、执行工具、推送事件）
  stream.ts  ← NDJSON 流式传输辅助

lib/
  agent-tools.ts  ← 工具定义（天气、计算器、时间、搜索）

app/api/agent/
  route.ts  ← 薄 handler，参数解析后调用 agent 模块
设计原则：route handler 仅负责 HTTP 层面的参数解析和错误处理， 所有业务逻辑下沉到 app/agent/ 模块中，方便单元测试和复用。

3. 核心 Agent 循环

Agent 的核心在 executor.ts 的 runAgentLoop 函数中。 它实现了一个经典的 ReAct（Reasoning + Acting）循环：

LLM 推理
→
有工具调用？
↓ 是
执行工具
→
返回结果
→
LLM 继续推理
→
循环...
否 ↓
输出最终回答，循环结束

3.1 循环伪代码

function runAgentLoop(llmWithTools, history, userMessage, onEvent) {
  messages = [...history, new HumanMessage(userMessage)]

  while (true) {
    response = await llmWithTools.invoke(messages)

    if (response 存在 tool_calls) {
      // 1. 记录 LLM 中间文本（如有）
      // 2. 将 AIMessage（含 tool_calls）加入上下文
      // 3. 逐个执行工具调用
      for (toolCall of response.tool_calls) {
        result = await executeTool(toolCall.name, toolCall.args)
        // 将 ToolMessage 加入上下文，供下轮使用
        messages.push(new ToolMessage(result))
      }
      // 继续循环，让 LLM 看到工具结果后继续推理
    } else {
      // 无工具调用 = 最终回答
      onEvent({ type: "final", content: response.content })
      break
    }
  }
}

3.2 消息上下文增长

每一轮循环，messages 数组会增长：

轮次 0: [历史消息...] + [用户消息]
         ↓ LLM 返回 tool_calls
轮次 1: [...上一轮] + [AIMessage(含 tool_calls)] + [ToolMessage(结果)] + ...
         ↓ LLM 返回 tool_calls
轮次 2: [...上一轮] + [AIMessage(含 tool_calls)] + [ToolMessage(结果)] + ...
         ↓ LLM 不再调用工具
最终:   [...全部上下文] + [AIMessage(最终回答)]

4. 流式传输协议（NDJSON）

Chat 类型使用纯文本流，而 Agent 类型使用 NDJSON（Newline-Delimited JSON） 流式传输协议。每行是一个独立的 JSON 对象，代表一个事件。

4.1 事件类型

事件类型 字段 说明
assistant content LLM 输出的中间文本（工具调用前的思考）
tool_call content, toolName, toolCallId LLM 请求调用某个工具
tool_result content, toolName, toolCallId 工具执行完毕，返回结果
final content, steps[] Agent 循环结束，包含最终回答和全部历史步骤
error content 不可恢复的错误

4.2 实际示例

用户提问："北京今天天气怎么样？温度换算成华氏度"

assistant {"type":"assistant","content":"让我先查一下北京的天气，再帮你换算。"}
tool_call {"type":"tool_call","content":"调用工具: get_weather","toolName":"get_weather","toolCallId":"call_abc1"}
tool_result {"type":"tool_result","content":"北京当前天气: 晴, 温度 25°C","toolName":"get_weather","toolCallId":"call_abc1"}
tool_call {"type":"tool_call","content":"调用工具: calculator","toolName":"calculator","toolCallId":"call_abc2"}
tool_result {"type":"tool_result","content":"计算结果: 25 * 9/5 + 32 = 77","toolName":"calculator","toolCallId":"call_abc2"}
final {"type":"final","content":"北京今天晴天，气温 25°C，换算成华氏度是 77°F。","steps":[...]}

4.3 客户端解析流程

前端 sendToAgent 函数使用 ReadableStream 逐块读取：

  1. 按 \n 分割缓冲区为独立行
  2. 每行 JSON.parse 解析为事件对象
  3. 根据 type 字段更新 UI（显示工具调用进度、展开思考过程等）
  4. 收到 final 事件后，保存完整消息到数据库

5. 各模块详解

5.1 types.ts — 类型定义

类型说明
AgentStepAgent 循环中记录的单个步骤（assistant / tool_call / tool_result）
AgentStreamEvent流式传输给客户端的事件（联合类型，含 5 种变体）
AgentEventCallback事件回调函数签名，执行器在每个事件发生时调用

5.2 llm.ts — LLM 客户端

  • resolveModel(model?) — 根据环境变量 OPENAI_MODELS 白名单校验模型名，非法则回退到第一个可用模型。
  • createToolCallingLLM(model) — 创建 ChatOpenAI 实例，读取 OPENAI_API_KEY 和 OPENAI_BASE_URL，调用 bindTools(allTools) 绑定所有工具后返回。
类型说明：bindTools() 返回的是 Runnable<BaseLanguageModelInput, AIMessageChunk>， 而非 ChatOpenAI 本身。模块中导出了 ToolCallingRunnable 类型别名以统一引用。

5.3 history.ts — 历史消息转换

buildHistory(conversationId) 从 SQLite 数据库加载对话消息， 仅选取 user 和 assistant 角色的消息，转换为 LangChain 的 HumanMessage / AIMessage。

为什么过滤掉 tool 消息？Tool 消息属于 Agent 中间执行细节， 不能作为独立对话轮次传给 LLM（OpenAI API 要求 tool 消息必须紧跟对应的 tool_calls AIMessage）。 历史重建时只保留 user/assistant 即可保证上下文完整性。

5.4 executor.ts — 执行器

核心函数 runAgentLoop 接收 4 个参数：

参数类型说明
llmWithToolsToolCallingRunnable已绑定工具的 LLM 实例
historyBaseMessage[]历史对话消息
userMessagestring用户新消息文本
onEventAgentEventCallback事件回调

内部辅助函数：

  • extractText(content) — 从 AIMessage 的 content 中提取纯文本，兼容字符串和结构化内容块数组两种格式。
  • executeTool(name, args) — 在 allTools 中查找并调用指定工具，返回字符串结果。

5.5 stream.ts — 流式辅助

  • encodeEvent(event) — 将事件对象序列化为 NDJSON 行（JSON + 换行符）。
  • createStreamCallback(enqueue) — 创建回调函数，桥接执行器与 HTTP ReadableStream。
  • createAgentResponse(body) — 构造标准 NDJSON 响应（设置 Content-Type 等头信息）。

5.6 route.ts — HTTP 入口

作为薄 handler，仅负责：

  1. 解析请求参数（conversationId、userMessage、model）
  2. 校验 API Key
  3. 调用 resolveModel → createToolCallingLLM → buildHistory
  4. 创建 ReadableStream，内部调用 runAgentLoop
  5. 异常时发送 error 事件
  6. 返回 NDJSON 流式响应

6. 工具系统

工具定义在 lib/agent-tools.ts 中，使用 LangChain 的 tool() 函数创建。 每个工具包含：名称、描述、参数 Schema（Zod）和执行函数。

工具名 功能 参数 当前状态
get_weather 查询城市天气 city: string 模拟数据（6 个城市）
calculator 计算数学表达式 expression: string 可用
get_current_time 获取当前时间 无 可用
web_search 网络搜索 query: string 模拟数据
如何新增工具？在 lib/agent-tools.ts 中用 tool() 定义新工具， 然后将其加入 allTools 数组即可。LLM 会根据工具的 name 和 description 自动决定何时调用。

7.2 UI 状态变化

  1. 发送前：用户输入消息，isTyping = false
  2. 请求中：isTyping = true，显示 loading 动画（三个跳动的点）
  3. 收到事件：
    • assistant — 更新 agentSteps，UI 展示思考文本
    • tool_call — 追加到 agentSteps，UI 展示工具调用名称
    • tool_result — 追加到 agentSteps，UI 展示工具结果
    • final — 设置 streamingContent，显示最终回答
  4. 完成：isTyping = false，将消息保存到数据库，更新本地状态

7.3 Agent 步骤展示组件

AgentSteps 组件将 Agent 的思考过程渲染为可折叠面板：

  • 默认折叠，显示工具调用次数摘要
  • 展开后依次展示：助手思考文本 → 工具调用 → 工具结果 → ...
  • 每种步骤有独立的颜色和图标区分

8. 数据库存储

Agent 类型对话在数据库中有额外的字段：

conversations 表

字段类型说明
typeTEXT'chat' 或 'agent'，默认 'chat'

messages 表

字段类型说明
roleTEXT扩展为 'user' / 'assistant' / 'tool'
tool_nameTEXT (可空)工具名称，仅 tool 角色消息有值
tool_call_idTEXT (可空)工具调用 ID，仅 tool 角色消息有值
兼容性：数据库通过 ALTER TABLE 迁移，已有数据不受影响。 历史对话自动归为 type = 'chat'。

10. 扩展指南

新增工具

在 lib/agent-tools.ts 中添加：

export const myNewTool = tool(
  async ({ param }) => {
    // 工具执行逻辑
    return "结果字符串";
  },
  {
    name: "my_new_tool",
    description: "工具描述（LLM 根据这段描述决定是否调用）",
    schema: z.object({
      param: z.string().describe("参数说明"),
    }),
  }
);

// 添加到导出数组
export const allTools = [weatherTool, calculatorTool, timeTool, webSearchTool, myNewTool];

接入真实搜索 API

将 webSearchTool 中的模拟实现替换为真实 API 调用即可，如 Tavily、Bing 或 Google：

export const webSearchTool = tool(
  async ({ query }) => {
    const response = await fetch(`https://api.tavily.com/search`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ api_key: process.env.TAVILY_API_KEY, query }),
    });
    const data = await response.json();
    // 提取并格式化结果
    return data.results.map(r => r.content).join("\n");
  },
  { /* name, description, schema 不变 */ }
);

限制工具调用轮次

在 runAgentLoop 中增加轮次计数器，防止无限循环：

const MAX_ITERATIONS = 10;
let iteration = 0;

while (continueLoop && iteration < MAX_ITERATIONS) {
  iteration++;
  // ... 原有逻辑
}
if (iteration >= MAX_ITERATIONS) {
  onEvent({ type: "error", content: "Agent 循环超过最大轮次限制" });
}

  return messages;
}
