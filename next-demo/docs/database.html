数据库表结构 SQLite

本文档整理项目中持久化存储所用的数据库表、字段、索引、外键关系及访问方式。

1. 概览

项目使用 SQLite 作为嵌入式数据库（通过 better-sqlite3 驱动）， 数据库文件位于 data/chat.db，由 lib/db.ts 单例管理。 启用 WAL 模式以提升并发读性能。共包含 2 张表、 2 个业务索引，承载对话（Chat / Agent）与消息的存储。

3. conversations 表

存储所有对话会话，区分普通对话（Chat）与智能体对话（Agent）。

字段 类型 约束 默认值 说明
id TEXT PRIMARY KEY — 对话唯一标识，创建时随机生成 8 位字符串
title TEXT NOT NULL '新的对话' 对话标题，可由用户修改
model TEXT NOT NULL 'gpt-4o-mini' 该对话使用的 LLM 模型名
type TEXT NOT NULL
CHECK IN ('chat','agent')		 'chat' 对话类型：普通对话 / 智能体
created_at TEXT NOT NULL datetime('now','localtime') 创建时间（本地时间，ISO 文本）
updated_at TEXT NOT NULL datetime('now','localtime') 最后更新时间，新增消息时自动刷新

3.1 建表语句

CREATE TABLE IF NOT EXISTS conversations (
  id         TEXT PRIMARY KEY,
  title      TEXT NOT NULL DEFAULT '新的对话',
  model      TEXT NOT NULL DEFAULT 'gpt-4o-mini',
  type       TEXT NOT NULL DEFAULT 'chat'
               CHECK(type IN ('chat', 'agent')),
  created_at TEXT NOT NULL DEFAULT (datetime('now', 'localtime')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now', 'localtime'))
);

4. messages 表

存储每条对话消息，包括用户输入、助手回复以及 Agent 模式下的工具调用结果。

字段 类型 约束 默认值 说明
id TEXT PRIMARY KEY — 消息唯一标识
conversation_id TEXT FOREIGN KEY → conversations(id)
ON DELETE CASCADE		 — 所属对话 ID
role TEXT NOT NULL
CHECK IN ('user','assistant','tool')		 — 消息角色：用户 / 助手 / 工具结果
content TEXT NOT NULL '' 消息正文内容
tool_name TEXT 可空 NULL 工具名称，仅 role='tool' 时有值（迁移新增）
tool_call_id TEXT 可空 NULL 工具调用 ID，仅 role='tool' 时有值（迁移新增）
created_at TEXT NOT NULL datetime('now','localtime') 创建时间，用于消息排序

4.1 建表语句

CREATE TABLE IF NOT EXISTS messages (
  id              TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  role            TEXT NOT NULL
                    CHECK(role IN ('user', 'assistant', 'tool')),
  content         TEXT NOT NULL DEFAULT '',
  tool_name       TEXT,
  tool_call_id    TEXT,
  created_at      TEXT NOT NULL DEFAULT (datetime('now', 'localtime')),
  FOREIGN KEY (conversation_id) REFERENCES conversations(id)
    ON DELETE CASCADE
);

5. 索引

为高频查询路径建立的索引（均使用 IF NOT EXISTS 幂等创建）。

索引名 所在表 字段 用途
idx_messages_conv_id messages conversation_id 按对话加载消息列表（最频繁的查询）
idx_conversations_updated conversations updated_at DESC 侧边栏按最近更新排序展示对话
sqlite_autoindex_conversations_1 conversations id 主键自动索引
sqlite_autoindex_messages_1 messages id 主键自动索引

6. Schema 迁移

为兼容历史数据库，lib/db.ts 在初始化时通过 ALTER TABLE 进行渐进式迁移（基于 pragma('table_info') 探测列是否存在）：

迁移项 操作 说明
conversations.type ADD COLUMN 旧库无此列时添加，默认 'chat'
messages.tool_name ADD COLUMN 旧库无此列时添加，支持 Agent 工具结果
messages.tool_call_id ADD COLUMN 旧库无此列时添加，关联工具调用
注意：SQLite 的 ALTER TABLE ADD COLUMN 无法附加 CHECK 约束到已有表的迁移列，因此 type 列的 CHECK 仅在建表语句中生效；对历史库迁移得到的列，约束在应用层保证。

7. 数据访问层（lib/db.ts）

所有数据库操作封装在此模块，对外暴露纯函数，避免直接拼接 SQL。

7.1 conversations 操作

函数说明
listConversations()列出全部对话，按 updated_at DESC 排序
getConversation(id)按 ID 查询单个对话
createConversation(id, title, model, type)新建对话
updateConversationTitle(id, title)更新标题并刷新 updated_at
updateConversationModel(id, model)更新模型并刷新 updated_at
touchConversation(id)仅刷新 updated_at（置顶用）
deleteConversation(id)删除对话及其全部消息（先删 messages 再删 conversation）

7.2 messages 操作

函数说明
getConversationMessages(conversationId)按 created_at ASC 加载对话的全部消息
addMessage(id, conversationId, role, content, toolName?, toolCallId?)新增消息，并自动 touchConversation 置顶对话

8. 设计约定

  • 主键：均为业务生成的 TEXT（随机字符串），便于跨服务引用。
  • 时间存储：统一使用 datetime('now', 'localtime') 生成本地时间文本。
  • 软排序：对话列表依赖 updated_at，消息列表依赖 created_at。
  • 级联删除：删除对话时通过外键 ON DELETE CASCADE 自动清理消息；代码层亦显式删除一次以兜底。
  • 单例连接：模块级缓存 _db，整个进程复用一个连接。
